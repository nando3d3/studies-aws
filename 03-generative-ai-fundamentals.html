03 — Fundamentos de IA Generativa (Domínio 2, 24%)

Foundation models

Um foundation model (FM) é um modelo grande e de propósito geral, pré-treinado num dataset vasto e diverso, projetado para ser adaptado a muitas tarefas subsequentes. Sinônimos usados de forma intercambiável: base model, modelo pré-treinado.

Um large language model (LLM) é um foundation model que implementa a arquitetura Transformer e trabalha principalmente na modalidade de texto. Nem todo foundation model é um LLM — o Stable Diffusion é um foundation model para imagens.

O ciclo de vida do foundation model

  1. Seleção de dados — reunir um corpus grande, diverso e licenciado
  2. Pré-treino — treino auto-supervisionado no corpus, produzindo um modelo base
  3. Fine-tuning / adaptação — especializar para uma tarefa, domínio ou comportamento
  4. Alinhamento — RLHF ou similar, para tornar as saídas úteis e inofensivas
  5. Avaliação — medir precisão, toxicidade, robustez
  6. Implantação — servir atrás de um endpoint
  7. Monitoramento / feedback — coletar uso real, iterar

Custos e trade-offs de foundation models

VantagemTrade-off
Não exige dados de treino nem expertise em ML pra começarCusto de inferência escala com tokens
Capacidade ampla entre tarefasPode alucinar; sem conhecimento de dados privados ou recentes
Rapidez pra gerar valorControle limitado sobre o comportamento do modelo base
Opções multimodais disponíveisModelos maiores custam mais e respondem mais devagar

Escolher um modelo é um trade-off entre custo, latência, modalidade, tamanho da janela de contexto, licenciamento e desempenho na tarefa. Um modelo pequeno como o Claude Haiku é mais barato e rápido; um grande como o Opus é mais capaz. A prova favorece "escolha o menor modelo que atenda ao requisito".

Arquitetura Transformer

Introduzida por pesquisadores do Google no artigo Attention Is All You Need. Substituiu RNNs e CNNs para NLP porque processa sequências em paralelo em vez de passo a passo, o que tornou viável escalar para bilhões de parâmetros.

Dois componentes:

ComponentePapel
EncoderLê e constrói um entendimento contextual da entrada
DecoderGera tokens de saída um de cada vez, condicionado à saída do encoder e ao que já foi produzido

Dois mecanismos fazem isso funcionar:

  • Multi-head attention — vários cálculos de atenção rodam em paralelo, cada um capturando um tipo diferente de relação entre tokens
  • Positional encoding — como os tokens são processados em paralelo, vetores de posição são somados aos embeddings para o modelo saber a ordem das palavras

Tipos de atenção

TipoDescriçãoOnde
Self-attentionCada elemento de uma sequência atende a todos os outros elementos da mesma sequênciaEncoder
Cross-attentionElementos de uma sequência atendem a uma sequência diferenteDecoder atendendo à saída do encoder (ex: tradução)
Multi-head attentionVários heads de atenção em paraleloAmbos

Atenção é calculada com Query, Key, Value (Q/K/V) — conceitualmente uma busca: a query é comparada com as keys, e os values correspondentes são retornados ponderados pela relevância.

Tokens

Um token é um pedaço de texto — aproximadamente uma palavra ou fragmento de palavra — mapeado para um ID inteiro único do vocabulário do modelo. Vocabulários típicos têm 30.000 a 100.000+ tokens.

TokenizadorUsado por
Byte Pair Encoding (BPE)GPT-3
WordPieceBERT
SentencePieceT5, GPT-3.5

Serviços gerenciados como o Bedrock tokenizam por você.

Por que tokens importam comercialmente: memória e computação crescem com o tamanho da sequência, e provedores cobram por token de entrada e por token de saída, geralmente a taxas diferentes. Entrada e saída dividem um único orçamento — um prompt muito longo deixa menos espaço pra resposta. A mitigação padrão para conversas longas é resumir os turnos anteriores e alimentar o resumo adiante.

Janela de contexto

A janela de contexto é o número total de tokens que um modelo pode considerar numa requisição — entrada mais saída combinadas. Tudo que você injeta (prompt de sistema, documentos recuperados, histórico da conversa, exemplos few-shot) consome essa janela.

Embeddings e espaço vetorial

Um embedding é um vetor numérico representando um pedaço de dado (texto, imagem, áudio) de forma que itens semanticamente similares fiquem próximos num espaço de alta dimensionalidade.

  • Um vetor tem magnitude e direção; um vector space model representa documentos como vetores de modo que a distância codifique similaridade.
  • Dimensionalidade é o número de valores no vetor. O modelo de embedding a determina, e ela precisa bater com a configuração do índice do seu vector store. Exemplo: all-MiniLM-L6-v2 produz 384 dimensões.
  • Modelos de embedding diferentes capturam relações diferentes — similaridade ortográfica, semântica, significado específico de domínio.
  • Similaridade é medida com similaridade de cosseno, distância euclidiana, ou produto escalar. Cosseno é o padrão comum.

Modelos de embedding no Bedrock: Amazon Titan Text Embeddings (v1, v2), Cohere Embed English, Cohere Embed Multilingual.

Parâmetros de inferência

ParâmetroEfeito
TemperatureControla aleatoriedade. 0 é determinístico e repetitivo; ~0,5 é um padrão equilibrado; 1,0 é maximamente criativo e pode degradar em nonsense.
Top-p (nucleus sampling)Considera apenas o menor conjunto de tokens cuja probabilidade acumulada excede p. Menor = mais focado.
Top-kConsidera apenas os k tokens seguintes mais prováveis.
Max tokens / tamanho da respostaLimita o tamanho da saída gerada.
Stop sequencesStrings que, quando geradas, encerram a resposta.

Para tarefas factuais e determinísticas (classificação, extração, geração de SQL) use uma temperature baixa. Para escrita criativa, aumente-a.

Engenharia de prompt

As três técnicas centrais

São as que mais importam pra prova.

TécnicaDefiniçãoQuando usar
Zero-shotDar a tarefa com instruções mas sem exemplosTarefas simples e bem entendidas
Few-shotFornecer vários exemplos de entrada/saída antes da entrada realVocê precisa de um formato de saída específico ou a tarefa é ambígua
Chain of Thought (CoT)Pedir ao modelo para raciocinar passo a passo antes de responderRaciocínio multi-etapa, matemática, lógica. Ajuda modelos menores desproporcionalmente.

One-shot é few-shot com exatamente um exemplo.

Elementos de um bom prompt

  • Instruções — o que fazer
  • Contexto — background que o modelo precisa
  • Dados de entrada — a coisa sobre a qual agir
  • Indicador de saída — o formato exigido
  • Negative prompting — declarar explicitamente o que não fazer ("não adicione informação que não está presente no texto")

Práticas específicas de modelo

Engenharia de prompt não é universal entre provedores.

  • O Anthropic Claude responde fortemente a tags XML delimitando seções (<context>, <question>, <document>). Claude também se beneficia bastante de Chain of Thought.
  • Modelos estilo OpenAI não dependem de tags XML da mesma forma.
  • Provedores diferentes usam formatos de requisição inteiramente diferentes (coberto em 04-amazon-bedrock.md).

Riscos de prompt

RiscoDescrição
Prompt injectionEntrada do usuário contém instruções que sequestram o comportamento do modelo
JailbreakingInjeção direta que sobrepõe ou revela o prompt de sistema
Prompt leakingInduzir o modelo a revelar seu prompt de sistema ou contexto confidencial
Poisoning / hijackingConteúdo malicioso plantado em documentos recuperados ou dados de treino

Mitigações: separar instruções de sistema do conteúdo do usuário, aplicar guardrails, restringir privilégios de backend, adicionar revisão humana, e validar qualquer coisa recuperada de fontes externas.

Retrieval Augmented Generation (RAG)

RAG recupera dados externos relevantes no momento da consulta e os injeta no prompt para que o foundation model responda com fatos nos quais nunca foi treinado. 

Pergunta do usuário
  → Gerar embedding da pergunta
  → Buscar os trechos mais relevantes na fonte de conhecimento
  → Inserir esses trechos no prompt como contexto
  → Foundation model gera uma resposta embasada

Pontos-chave para a prova:

  • RAG não modifica o modelo. Nenhum peso muda. Só muda o que está na janela de contexto.
  • RAG não se limita a vector stores. Um pipeline de RAG pode recuperar da internet, de um banco relacional, de um banco de grafos, ou de um banco de documentos. Busca vetorial é só a implementação mais comum para recuperação semântica.
  • RAG é como você lida com dados privados, proprietários ou que mudam com frequência, e como você reduz alucinação embasando respostas em fontes citáveis.
  • O limite do RAG é a janela de contexto e o custo dos tokens que você injeta.

RAG vs. fine-tuning vs. engenharia de prompt

A questão de cenário mais provável desta prova.

AbordagemCustoMuda os pesos?Quando usar
Engenharia de promptMais baixoNãoO modelo base já consegue fazer isso com instruções melhores
RAGBaixo–médioNãoVocê precisa de fatos atuais, privados ou citáveis
Fine-tuningAltoSimVocê precisa de um comportamento, formato, tom ou tarefa específico que o modelo base faz mal
Continued pre-trainingMais altoSimVocê precisa ensinar um domínio de conhecimento geral inteiramente novo
Treinar do zeroExtremoN/AQuase nunca é a resposta certa nesta prova

Mnemônico: RAG adiciona conhecimento, fine-tuning adiciona habilidade.

Fine-tuning

Fine-tuning retreina os pesos de um modelo pré-treinado num dataset menor e rotulado. A saída é um novo conjunto de pesos de modelo, não código de modelo novo.

Pelo que o dataset ensina

TipoDadosPropósito
Instruction fine-tuningPares prompt/completionEnsinar o modelo a seguir um padrão de instrução específico
Domain-specific fine-tuningCorpus de domínioAdaptar vocabulário e conhecimento a uma vertical
Continued pre-trainingDados não rotuladosAmpliar conhecimento geral num domínio
Supervised fine-tuning (SFT)Dados rotuladosMelhorar desempenho numa tarefa específica

Rotulado vs. não rotulado é o discriminador que a prova usa: fine-tuning = dados rotulados, específico da tarefa. Continued (continuous) pre-training = dados não rotulados, conhecimento geral.

Por quanto do modelo muda

MétodoDescrição
Full fine-tuningAtualiza todos os pesos. Mais caro, mais capaz.
Parameter-Efficient Fine-Tuning (PEFT)Congela a maior parte do modelo e treina um pequeno conjunto de parâmetros adicionados. Muito mais barato. LoRA é o método PEFT mais conhecido.
Last-layer fine-tuningCongela tudo exceto a camada final
PruningRemove parâmetros para reduzir o modelo

RLHF

Reinforcement Learning from Human Feedback alinha um modelo com preferências humanas: humanos ranqueiam saídas do modelo, um modelo de recompensa é treinado sobre esses ranqueamentos, e o modelo é otimizado contra o modelo de recompensa. É isso que transforma um modelo pré-treinado bruto num assistente útil. Relacionado: o Amazon A2I e os fluxos de avaliação humana do Bedrock fornecem o componente de julgamento humano.

Agentes

Um agente é um LLM ao qual foi dada autonomia para decidir quais ações tomar. Ele pode chamar ferramentas (tools) (funções, APIs, Lambda), consultar knowledge bases, e encadear múltiplos passos para satisfazer uma requisição.

ConceitoSignificado
Tool use / function callingO modelo escolhe invocar uma função externa e fornece os argumentos
AgênciaO modelo decide a sequência de passos; você não a programou
Orquestração / workflowVocê define explicitamente a sequência; o modelo preenche os passos generativos

Agêntico (Bedrock Agents) versus orquestrado (Bedrock Prompt Flows, cadeias LangChain) é uma comparação recorrente.

Arquiteturas de modelo que vale nomear

ArquiteturaPropósito
TransformerLLMs modernos; baseado em atenção

VAE (Variational Autoencoder)Codifica dados num espaço latente e decodifica de volta; usado em geração

Casos de uso de negócio e métricas

Aplicações comuns de IA generativa: chatbots e assistentes virtuais, resumo, tradução, geração de código, criação de conteúdo, geração de imagem, busca e recuperação de conhecimento, personalização, processamento de documentos, e desvio de atendimento ao cliente.
