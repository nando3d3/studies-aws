02 — Fundamentos de IA e ML (Domínio 1, 20%)

A hierarquia de aninhamento

Artificial Intelligence
└── Machine Learning
    └── Deep Learning (redes neurais)
        └── Generative AI
            └── Large Language Models
TermoDefinição
Artificial IntelligenceMáquinas realizando tarefas que imitam o comportamento humano ou normalmente exigem inteligência humana. IA simula inteligência (imita comportamentos); não emula (não replica o mecanismo exato).
Machine LearningSistemas que melhoram numa tarefa a partir de dados, sem serem reprogramados explicitamente para cada novo caso.
Deep LearningML usando redes neurais artificiais com múltiplas camadas. Regra prática: 3 ou mais camadas ocultas = deep.
Generative AIIA que cria conteúdo novo — texto, imagem, áudio, vídeo, estruturas moleculares — em vez de só analisar dados existentes.
Large Language ModelUm foundation model construído sobre a arquitetura Transformer que prevê o próximo token de texto.

IA vs. IA Generativa na prova: a IA tradicional entende, classifica e decide sobre dados existentes; a IA generativa produz saída nova, nunca vista antes. IA generativa é um subconjunto, não um substituto.

Modalidades de IA generativa

ModalidadeExemplo de saída
TextoArtigos, resumos, código
VisãoImagens e vídeo
ÁudioFala, música
MolecularCompostos candidatos para descoberta de fármacos

Modelos multimodais lidam com mais de uma modalidade (ex: entrada de imagem + texto).

Tipos de problema de aprendizado

Os três tipos primários

TipoDadosGuiado porTarefas típicas
SupervisionadoRotuladosTarefaClassificação, regressão
Não supervisionadoNão rotuladosDadosClusterização, associação, redução de dimensionalidade
Por reforçoSem dataset pré-existenteRecompensa/feedbackJogos, robótica, navegação autônoma

Aprendizado supervisionado é mais preciso, mas exige rotulagem cara antecipadamente. O não supervisionado encontra estrutura de graça, mas precisa de um humano para interpretar se os padrões descobertos significam algo.

Aprendizado por reforço usa um agente agindo em um ambiente, recebendo recompensas ou penalidades, aprendendo por tentativa e erro. Não há dataset de treino de partida.

Aprendizado híbrido

TipoDescrição
Semi-supervisionadoUm pequeno conjunto rotulado mais um grande conjunto não rotulado
Auto-supervisionadoO modelo gera seus próprios rótulos a partir dos dados (como LLMs são pré-treinados)
Multi-instânciaExemplos são agrupados em "bags" rotuladas em vez de rotulados individualmente

Técnicas de aprendizado

TécnicaDescrição
Transfer learningUm modelo treinado numa tarefa é reaproveitado como ponto de partida para uma tarefa relacionada. É a base conceitual do fine-tuning.
Ensemble learningVários modelos são treinados e suas previsões combinadas (bagging, boosting, stacking). Útil quando a qualidade dos dados é um problema.
Active learningO modelo consulta um humano durante o treino quando está incerto.
Online learningO modelo se atualiza continuamente conforme novos dados chegam.
Multitask learningUm modelo resolve vários problemas relacionados ao mesmo tempo.

As quatro formas clássicas de problema de ML

Decore esta tabela — ela recorre constantemente.

ProblemaRotulado?SaídaExemploAlgoritmos
RegressãoSimNúmero contínuoPrever a temperatura de amanhã; preço de casaLinear, polinomial, SVR, árvore de decisão, random forest de regressão
ClassificaçãoSimClasse discretaSpam vs. não spam; chuva vs. solRegressão logística, KNN, SVM, Naive Bayes, árvore de decisão, random forest, redes neurais

Redução de dimensionalidade é uma quinta forma, geralmente um passo de pré-processamento: reduzir o número de features preservando informação. Algoritmos: PCA, LDA, SVD, t-SNE.

Pegadinha comum: se a questão diz que os dados não têm rótulos, a resposta é clusterização ou associação, nunca classificação ou regressão.

Redes neurais

Uma rede neural é um grafo de neurônios (nós) organizados em camadas, conectados por arestas com pesos.

Camada de entrada → Camada(s) oculta(s) → Camada de saída
ConceitoDefinição
Feed-forward network (FNN)Conexões nunca formam ciclo; dados fluem numa direção
BackpropagationApós um passo à frente, o erro é propagado para trás para ajustar os pesos. É assim que a rede aprende.
Loss functionCompara a previsão com a verdade de referência para produzir um valor de erro
Activation functionAplicada num nó para determinar seu sinal de saída
Dense layerCamada com número crescente de nós
Sparse layerCamada com número decrescente de nós
PerceptronA rede neural mais simples — um classificador binário com camada de entrada e de saída

A camada de entrada não transforma dados; é só um ponto de entrada. O número de nós de entrada é igual à dimensionalidade do vetor de entrada.

Funções de ativação

Funções de ativação lineares não sustentam backpropagation e não podem ser empilhadas. As não lineares podem — por isso toda rede prática usa não lineares.

FunçãoIntervaloNotas
Linear / IdentityIlimitadoSem benefício de aprendizado; derivada constante
Binary step0 ou 1A mais antiga; só classificação binária; raramente usada hoje
Sigmoid0 a 1Curva S suave; sofre de gradiente evanescente; ativação densa, lenta
Tanh−1 a 1Sigmoid escalonada, gradientes mais fortes, ainda evanesce
ReLU0 a ∞Rápida, ativação esparsa, a escolha padrão; sofre de dying ReLU (neurônios travados em 0)
Leaky ReLU−∞ a ∞Pequena inclinação negativa evita o dying ReLU
Parametric ReLU—Leaky ReLU com inclinação negativa aprendida/fixa (comumente 0,01)
ReLU-60 a 6ReLU limitada no lado positivo
ELU−1 a ∞Exponencial no lado negativo; convergência mais rápida
Swish—Google Brain; alternativa suave e não monotônica à ReLU
Maxout—Retorna o máximo entre várias entradas; dobra os parâmetros
Softmax0 a 1, soma 1Camada de saída para classificação multiclasse; produz uma distribuição de probabilidade

Dois problemas nomeados para reconhecer:

  • Gradiente evanescente — gradientes encolhem para perto de zero em redes profundas, então as primeiras camadas param de aprender. Associado a sigmoid e tanh.
  • Dying ReLU — neurônios produzem zero permanentemente e param de contribuir.

Modelos, parâmetros e inferência

TermoDefinição
AlgoritmoUm conjunto de instruções para realizar uma tarefa
ModeloUma função que recebe dados, aplica um algoritmo e produz uma previsão
FeatureUma propriedade mensurável individual extraída de dados brutos — uma coluna em dados tabulares
Feature engineeringExtrair, limpar e transformar dados brutos em features legíveis por máquina. Modelos de ML consomem números, então texto e categorias precisam ser codificados.
InferênciaSolicitar e receber uma previsão de um modelo implantado. A saída tipicamente inclui um score de confiança.
Ground truthDados corretamente rotulados usados como padrão objetivo para treino e avaliação

Model drift

Um modelo em produção se degrada com o tempo conforme os dados do mundo real divergem dos dados de treino. Isso é model drift (levando a model decay). O Amazon SageMaker Model Monitor detecta isso.

Processamento de linguagem natural

NLP fica na intersecção entre ciência da computação e linguística: entender o contexto de um corpus (um grande corpo estruturado de texto).

Vocabulário de pipeline que vale reconhecer:

EtapaTermos

Conceitos de dados

Rotulagem de dados e ground truth

Rotulagem é identificar dados brutos e anexar tags significativas — pré-requisito para aprendizado supervisionado. O Amazon SageMaker Ground Truth é o serviço gerenciado para isso. A precisão do modelo nunca pode superar a qualidade da sua ground truth.

Mineração de dados e CRISP-DM

Mineração de dados extrai padrões e conhecimento de grandes datasets — não os próprios dados.

CRISP-DM, a metodologia de seis fases:

  1. Entendimento do negócio
  2. Entendimento dos dados
  3. Preparação dos dados
  4. Modelagem
  5. Avaliação
  6. Implantação

Data wrangling

Transformar dados brutos num formato mais valioso. Seis passos:

  1. Descoberta
  2. Estruturação
  3. Limpeza (outliers, nulos, duplicatas, formatação)
  4. Enriquecimento (juntar contexto adicional)
  5. Validação (checagens de qualidade e confiabilidade)
  6. Publicação (gravar num data store)

Ferramentas AWS: SageMaker Data Wrangler (focado em ML) e AWS Glue DataBrew (uso geral).

O fluxo de trabalho de ML da AWS

A AWS documenta o ciclo de vida de ML como fases contendo passos:

  1. Buscar (Fetch) — coletar dados de um repositório, dataset público, ou sistema de origem
  2. Limpar (Clean) — normalizar valores inconsistentes
  3. Preparar (Prepare) — transformar e criar features
  4. Treinar (Train) — selecionar um algoritmo e treinar o modelo
  5. Avaliar (Evaluate) — medir precisão contra dados reservados
  6. Implantar (Deploy) — hospedar o modelo para inferência
  7. Avaliar continuamente — monitorar drift, coletar ground truth, retreinar

Espere questões de ordenação sobre essa sequência.
